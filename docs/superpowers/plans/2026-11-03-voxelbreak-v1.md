# VoxelBreak v1 - план этапов

Дата: 03.11.2026. Основа: замысел `docs/superpowers/specs/2026-10-17-voxelbreak-design.md` (одобрен 24.10) и
дополнение 31.10 (модели из Blender потом, сейчас кодом через слой `assets/`). Ветка `claude/voxelbreak-v1`.

## Устройство (решения)

- `web/` - весь сайт без сборки: ES-модули, three.js лежит в `web/vendor/`. Те же файлы открывает Electron
  через свою схему `app://` (на `file://` модули и Worker в Chromium не работают).
- Ядро без окон (`web/js/core/`): воксели, чанки 32³, генерация, связность, физика обломков, сохранение,
  жадная сетка. Чистые функции и классы без DOM и без three.js - их проверяет `node --test` с покрытием c8.
- Окно (`web/js/app/`): отрисовка three.js, звук WebAudio, меню и HUD. Проверяется Playwright.
- Масштаб: 1 воксель = 0,25 м. Мир по умолчанию 12×3×12 чанков (96 × 24 × 96 м). Материал - один байт.
- Сетка чанка строится жадно (грани с одинаковым материалом и затенением углов сливаются), в Worker.
  Пёстрость по вокселю даёт шейдер по хешу мировых координат, поэтому слияние граней её не портит.
- Разрушение: удар убирает воксели по силе и прочности материала, затем поиск связности от соседей
  удалённого - «лучший сначала вниз» до опоры (коренная порода). Не дошёл до опоры - кусок вырезается
  из мира и становится телом со своей воксельной сеткой.
- Физика своя: тело - воксельная сетка + положение + кватернион; точки касания - поверхностные воксели;
  импульсы с трением, усыпление неподвижных, бюджет (мелочь в пыль, предел числа тел).
- Слой `assets/`: `web/assets/manifest.json` перечисляет модели. Источник `proc:имя` (кодом) или `*.glb`
  (свой разбор GLB и перевод треугольников в воксели). Игра берёт модели только через `assets.load(id)`.

## Этапы

| № | Этап | Часы | Законы |
| - | ---- | ---- | ------ |
| 0 | Каркас: package.json, web/, three в vendor, node:test + c8, правило приватности | 1 | личного нет |
| 1 | Воксели: материалы, чанк, мир, ГПСЧ и шум | 1-2 | запись/чтение, границы мира |
| 2 | Генерация: рельеф, город, природа, случайный мир; модели кодом через assets | 2-3 | детерминизм по зерну, порядок чанков не важен |
| 3 | Жадная сетка + затенение углов, Worker | 2 | нет дыр и лишних граней, швы чанков |
| 4 | Удар, связность, отрыв кусков | 2-3 | висящих кусков нет, масса сохраняется, взрыв R убирает ожидаемое |
| 5 | Физика обломков: столкновения, трение, сон, бюджет, раскол тел | 3 | кусок без опоры падает и ложится, без проникания, детерминизм |
| 6 | Сохранение мира, тел и игрока | 1-2 | туда-обратно, испорченный файл не роняет |
| 7 | Окно: сцена, чанки, тела, игрок, захват мыши, HUD | 3 | страница открывается, WebGL рисует, ошибок нет |
| 8 | Инструменты: молот, руки, динамит, бочки, дробовик, ракетница, лазер | 3 | цепная реакция, лазер режет, руки толкают |
| 9 | Техника: машина, бульдозер, кран с шаром | 2-3 | таран ломает, шар маятником |
| 10 | Меню: 5 тем, ru/en, переназначение клавиш, настройки | 2 | читаемость тем, узкое окно, все строки переведены |
| 11 | Звук кодом, частицы, вспышки | 1-2 | звук не падает без AudioContext |
| 12 | Слой assets: GLB → воксели, персонаж со скелетом кодом | 2 | GLB-куб даёт ожидаемые воксели |
| 13 | Electron: окно, схема app://, тестовый режим | 2 | невидимое окно, 20 запусков без роста памяти |
| 14 | Производительность и мутанты (`tools/mutate.js`) | 2 | кадр в пороге на эталонной сцене; каждый закон ловит мутанта |
| 15 | CI, Pages, README en/ru, снимки, гифка, CHANGELOG, черновик PR | 2 | порог покрытия в CI |

Каждый найденный недочёт: сначала закон, который его ловит, потом исправление.

## Пороги

- Покрытие по ветвям: ядро (`web/js/core/`) >= 90 %, весь код без окон >= 80 % (`tools/coverage-check.js`).
- Кадр: на эталонной сцене (зерно 7, взрыв R = 6 в доме) шаг физики со всеми обломками не дольше 8 мс
  в среднем и 25 мс в худшем на машине CI; обработка самого взрыва - не дольше 150 мс.
